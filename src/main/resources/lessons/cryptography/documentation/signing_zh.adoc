= 签名

签名是一种可用于检查数据有效性的哈希值。签名可以与其验证的数据分开提供；也可以像 CMS 或 SOAP 一样包含在同一个文件中（文件的一部分存储数据，另一部分存储签名）。

当完整性很重要时，就会使用签名。签名旨在保证从 A 方发送到 B 方的数据未被篡改。因此，A 方会计算数据的哈希值，并使用非对称私钥对该哈希值加密。随后 B 方可以重新计算数据哈希值，并解密签名，比较两个哈希值是否一致。

== 原始签名

A 方通常按以下方式计算原始签名：

* 创建数据哈希值（例如 SHA-256 哈希）
* 使用非对称私钥加密哈希值（例如 2048 位 RSA 密钥）
* （可选）使用 Base64 编码加密后的二进制哈希

B 方也需要获取包含公钥的证书。该证书可能已经提前交换。因此至少涉及三个文件：数据、签名和证书。

== CMS 签名

CMS 签名是一种标准化方式，可将数据、签名和包含公钥的证书一起放在一个文件中，从 A 方发送给 B 方。只要证书有效且未被撤销，B 方就可以使用随附的公钥验证签名。

== SOAP 签名

SOAP 签名也可以在同一个 XML 载荷中包含数据、签名以及可选的证书。计算数据哈希值时有一些特殊步骤，因为 SOAP XML 在系统之间传输时可能会加入额外元素或时间戳。
此外，SOAP 签名支持由不同参与方对消息的不同部分分别签名。

== 电子邮件签名

发送电子邮件并不难：填写一些数据并发送到会转发邮件的服务器，最终邮件就会到达目的地。不过，发送邮件时可以使用并非自己的 FROM 地址。为了向收件人保证邮件确实由你发送，你可以对邮件签名。受信任的第三方会验证你的身份并签发电子邮件签名证书。你可以将私钥安装到电子邮件应用中，并配置应用对发送的邮件签名。证书对应一个特定的电子邮件地址，所有收到该邮件的人都会看到发件人已验证的标志，因为他们的工具会使用受信任第三方签发的公钥证书验证签名。

== PDF、Word 等文档签名

Adobe PDF 和 Microsoft Word 文档也支持签名。签名与数据一起保存在同一文档中，因此文件中会有说明，用于标明哪些部分属于数据，哪些部分属于元数据。
政府通常会使用包含证书的 PDF 发送正式文件。

== 练习

这是一个简单练习。我们会提供一个 RSA 私钥。请确定 RSA 密钥的模数（以十六进制字符串表示），并使用该密钥为该十六进制字符串计算签名。本练习需要一些 OpenSSL 使用经验。你可以在互联网中搜索有用命令，和/或点击 HINTS 按钮查看提示。
