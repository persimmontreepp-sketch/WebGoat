= 密钥库与信任库

密钥库存储密钥。除了 *_keystore_* 之外，也经常使用 *_truststore_*（信任库）一词。信任库与密钥库相同，只是通常只包含受信任证书或证书颁发机构的证书（也就是公钥和签发者信息）。

== 基于文件的密钥库

基于文件的密钥库最终会将密钥保存在文件系统中。
将公共证书存储在基于文件的密钥库中非常常见。

== 数据库密钥库

密钥，尤其是公共证书，也可以存储在数据库中。

== 硬件密钥库

硬件密钥库是一种通过某种硬件来保存实际密钥的系统。它通常用于高级别安全环境，确保私钥真正私密。
与基于文件或数据库的密钥库相比，无法复制硬件密钥库并将副本发送到未知或不可信的环境。

一些为网站提供服务器证书的证书颁发机构也会代为生成私钥（作为服务）。但严格来说，此时的密钥不再是私钥。对于所有类型的密钥库，都应对私钥严格保密，并使用证书签名请求申请签名证书或服务器证书。

== 操作系统、浏览器和其他应用中的受管理密钥库

访问网站时，如果浏览器显示证书正常，意味着该网站使用的证书由受信任的证书颁发机构签发。但此受信任证书颁发机构列表是可管理的：某些 CA 可能会被撤销或移除。安装浏览器更新时，通常会在后台完成这些更新。
不只有浏览器维护受信任 CA 列表，操作系统也会维护。Java 运行时同样有自己的列表，保存在 cacerts 文件中。操作系统和 Java JRE 更新会保持此列表最新。在企业环境中，列表通常由公司维护，也会包含公司的根证书。

== 使用 DNS CAA 记录对网站证书进行额外检查

有些公司会检查全部或大部分互联网流量，甚至包括你认为已实现端到端安全连接的流量。过程如下：员工打开浏览器并搜索信息；浏览器通过 HTTPS 访问 Google。链接看起来真实，浏览器中也显示锁形图标。然而，如果查看证书，可能会发现证书是由公司根 CA 签发的！也就是说，你与公司服务器建立了端到端安全连接，而该服务器再与 Google 建立安全连接。
为了防止服务器受到此类中间人连接，现代浏览器还会检查 DNS CAA 记录，以确认特定签发者是否有权为特定网站签发证书。
更多信息：https://en.wikipedia.org/wiki/DNS_Certification_Authority_Authorization[维基百科 DNS CAA,window=_blank]

== 来自 Let's Encrypt 的免费证书

https://letsencrypt.org[Let's Encrypt,,window=_blank] 是一个免费、自动化且开放的证书颁发机构。它允许你为自己控制的网站创建有效证书。遵循并实施特定协议后，系统会验证你的身份并签发证书。证书免费提供，旨在鼓励使用经授权的证书，并减少互联网上自签名证书的使用。证书有效期为 90 天，因此需要自动续期。（这也能确保身份/所有权经常得到验证。）
