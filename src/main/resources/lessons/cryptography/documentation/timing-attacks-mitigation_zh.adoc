=== 检查修复方法

易受攻击的比较方法会在检测到依赖机密的不匹配时提前退出：

[source,java]
----
for (int i = 0; i < expected.length; i++) {
    if (expected[i] != provided[i]) {
        return false;
    }
}
----

加入随机延迟会增加测量成本，但重复采样仍然可能揭示信号。将值转换为字符串，只会把同一种比较错误转移到另一个 API 中。

请找出根本原因，并选择能够消除问题的修复方法。应用代码应使用专门用于比较认证值的库方法，而不是自行编写循环并假设它具有恒定时间行为。

Java 无法保证在所有 JIT、缓存、调度程序、运行时和硬件条件下都具有完全相同的 CPU 执行时间。实用原则是避免有意实施依赖机密的提前退出，并使用适当的库原语，例如 `MessageDigest.isEqual(expected, provided)`。
