安全部署不只是编写安全的代码，还要确保平台每次发布时都经过加固。
在本课程中，你利用并修复了四种常见错误：

* **仍启用默认凭据。**
删除厂商账户，要求首次启动时更换密码，并将访问权限关联到集中式身份系统。
* **生产环境返回详细调试错误。**
将堆栈跟踪写入日志，而非显示给用户；只向用户展示友好的错误消息。
* **管理端点/控制台暴露。** 将管理端点限制为可信网络访问，并要求身份验证。
* **配置加固不足。** 禁用不需要的端点，隐藏健康检查详情，并清除嵌入式管理员账户，防止其再次出现。

将以下检查纳入交付流水线：

* 为每种环境维护配置基线清单。
* 使用基础设施即代码和配置扫描来自动执行加固。
* 将暂存环境标志视为临时设置，确保在正式发布前移除。
* 定期审计变更，避免配置漂移重新引入同类漏洞。

安全配置错误一旦出现，攻击者无需破解加密或发现新漏洞——他们只需利用平台已经暴露的内容。
严格维护配置卫生，就能消除他们最容易利用的攻击路径之一。
