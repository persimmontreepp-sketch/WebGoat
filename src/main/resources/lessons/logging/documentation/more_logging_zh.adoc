==== 审计日志、安全事件监控和应用日志
请注意，日志记录的用途远不止应用调试。应用日志通常会提供给其他用途，例如：

 - *审计日志*：应用需要记录特定事件，以形成可追溯记录，从而重建代表用户或由用户执行的操作。之后例如可在发生争议时于法庭中用于证明事实。
 - *安全事件监控（SEM）*：应用生成的事件通常可供安全部门了解组织应用环境中发生的情况。为了检测组织是否面临风险，可能需要分析多种事件及属性。例如，仅用于紧急情况下的特权管理员登录，本身就是非常有价值的事件。另一个例子是：频繁使用的管理员登录值得记录，但仅凭这些记录未必会触发安全事件，除非该管理员角色从完全不同的位置登录。与安全部门一起进行威胁建模，通常有助于确定需要哪些日志，以及哪些日志应立即触发安全警报。
 - *欺诈检测*：应用日志有助于检测欺诈。例如，日志显示有人试图转移超出其拥有金额的钱款，这可能意味着出了问题。
 - *业务流程监控*：可通过应用日志观察业务流程是否按预期推进。例如，流程后续阶段迟迟没有新事件，可能说明业务流程已停止。对于业务管理来说，这是非常有价值的信息。
 - *还有许多其他用途……*

请注意，上述日志用途之间可能存在很大差异！因此，最好在应用输出、组织内的日志存储和处理方面，将应用（调试）日志与 SEM 和审计日志分开。
