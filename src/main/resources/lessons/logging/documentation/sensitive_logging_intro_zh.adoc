=== 更多日志记录知识

如你所见，当用户试图伪造日志时，就可能引发日志伪造问题。除了表单 POST，还可以通过多种方式实现，例如 URL 参数或精心构造的 JSON 载荷。因此，以下事项非常重要：

- 正确清理输入；
- 确保能够确定数据来源的真实性，并实施完整性控制以检测日志篡改；
- 确保用户无法通过任何渠道注入日志；
- 保护日志存储。

但日志安全不仅仅是清理输入以防止伪造攻击。我们还来看看敏感信息的日志记录问题。

==== 记录敏感信息

在上一项练习中，我们只看到用户名经过，没有看到密码。为什么？因为我们要确保应用日志不包含任何敏感信息。这样，即使日志遭到泄露，也不必担心身份验证信息被他人重复使用。

同样地，也不应记录其他敏感信息，例如对称密钥、私钥和访问令牌。

==== 记录个人信息

记录个人信息时要小心。例如，不要记录银行账户详情，也不要记录用户未同意被记录的个人身份信息。不要记录能够确定日志所涉及对象身份的事实。

基本上，你要防止他人利用日志对人进行画像或监视。应保护使用系统的人员的隐私。

===== 特殊情况：访问日志

一个特殊情况是入口服务器和/或应用服务器生成的访问日志。这些日志至少应包含一些信息：请求来源、请求时间，以及可能的响应代码。根据日志的安全性，还可以记录其他信息。例如，为保护用户隐私，不应在访问日志中保存原始请求内容。

问题往往就从这里开始：访问日志有时会记录请求使用的完整 URL，其中可能包含敏感 URL 参数。因此，要谨慎选择 URL 参数，并确保不将这些参数记录在公开可访问的日志中。
