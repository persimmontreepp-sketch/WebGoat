= 扩展 HTTP

== HTTPS 与 TLS

HTTP 协议有一个重大缺陷：客户端与服务器之间传输的所有流量都没有加密。这意味着任何人都能通过简单的中间人攻击读取流量。HTTPS（安全超文本传输协议）通过多种密码学机制，为不安全的 HTTP 协议提供*机密性*和*完整性*。

`传输层安全性`（`TLS`）是一种协议，用于建立客户端与服务器之间的加密连接，同时验证连接中传输的数据是否遭到篡改。HTTPS 使用 TLS 来保护 HTTP 协议。

随着安全数据传输日益重要，HTTPS 得到了广泛应用。如今，浏览器会将所有纯 HTTP 流量标记为不安全，搜索引擎也会优先显示 HTTPS 结果。这标志着与早期做法相比发生了显著转变，下面将深入了解 HTTPS 如何实现安全性。

=== TLS 证书如何保护 HTTP？

=== 机密性

TLS 通过在客户端和服务器之间建立加密连接来保护机密性。它使用 https://en.wikipedia.org/wiki/Public-key_cryptography[公钥密码学]和 Diffie–Hellman 等密钥交换算法安全地协商共享密钥，然后使用这些密钥加密连接中发送的所有数据。这样可以防止拦截流量的人读取内容，帮助确保敏感信息保持私密。

请阅读 https://www.cloudflare.com/learning/ssl/what-happens-in-a-tls-handshake/[Cloudflare 的文章]，进一步了解 TLS 握手，以及建立加密连接时幕后发生的事情。

=== 完整性

每个支持 TLS 的服务器都有一个包含公钥的 `证书`，以及与之分离的私钥。如果网站部署在互联网上，该证书几乎总是由`证书颁发机构`签署。`证书颁发机构`是受信任的公司，负责颁发和验证数字证书，以证明域名所有权。签名证书对完整性至关重要，因为它通过密码学方式验证网站身份，确保你所连接的网站正是其声称的网站，且确实拥有其域名。
