== 存储 JWT 令牌

收到 JWT 令牌后，需要将其存储在客户端。基本上有两种选择：

- 将令牌存储在 Cookie 中
- 将令牌存储在本地/会话存储中

=== Cookie

Cookie 是最简单的方式，长期以来所有浏览器都支持 Cookie。最佳实践是将 Cookie 标记为 `HttpOnly`，确保脚本无法读取它；同时设置 `Secure`，确保 Cookie 只通过 HTTPS 发送。

注意：使用 Cookie 并不意味着必须像以前的会话 Cookie 那样在服务器上维护状态。JWT 令牌是自包含的，可以/应该包含实现完全无状态所需的全部信息；Cookie 只用作传输机制。

=== Web 存储

这种情况下，令牌会存储在客户端 HTML5 Web Storage 中。

=== 选择与安全风险

同一域名下运行的 JavaScript 可以访问 Web 存储。因此，如果网站存在跨站脚本攻击漏洞，脚本就能读取 Web 存储中的令牌。有关此攻击的工作方式，请参阅 XSS 课程。

另一方面，使用 Cookie 也有不同问题：Cookie 容易受到跨站请求伪造攻击。此时攻击者会尝试在你持有令牌的网站上触发操作。有关此攻击的工作方式，请参阅 CSRF 课程。

最佳建议是选择基于 Cookie 的方式。实际上，防御 CSRF 攻击更容易。另一方面，许多 JavaScript 框架会通过正确编码来保护用户免受 XSS 攻击，这种保护是开箱即用的。有些框架默认不提供 CSRF 防护，需要额外工作。最终应根据框架提供的功能进行选择，但在大多数情况下，XSS 攻击会给攻击者带来更大的操作空间。
