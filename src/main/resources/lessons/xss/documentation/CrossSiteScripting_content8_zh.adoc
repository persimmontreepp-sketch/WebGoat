== XSS 防御

=== 为什么要防御？
希望现在已经很清楚：你不希望他人的代码在用户的上下文和登录会话中运行。

=== 应编码什么？
XSS 防御的基本原则是对任何不可信输入进行*输出编码*，然后再显示到页面上。
面对更复杂的攻击时，做法或许需要调整，但这是目前最好的防御方式。*并且*……*上下文很重要*。

再说一点关于“不可信输入”的内容：如果有疑问，就把所有内容都视为不可信（即使是你放进数据库的数据）。有时数据会在多个系统间共享，你以为由自己/团队创建的数据，实际上可能不是。

=== 何时/何处编码？
在数据发送到浏览器时编码（不要在持久化数据中编码）。对于*单页应用（SPA）*，需要在客户端编码。详情请参阅你使用的框架/库；下一页会提供一些参考资料。

=== 如何编码？

* 在 HTML 正文中将数据编码为 HTML 实体
* 在 HTML 属性中将数据编码为 HTML 实体
* 如果将用户输入输出到 JavaScript 中，则按 JavaScript 上下文进行编码（不过请想一想……你真的要在页面的 JavaScript 中输出用户输入吗？）

*不要*尝试将 `'<script>'` 等字符串列入黑名单/负面过滤列表。
