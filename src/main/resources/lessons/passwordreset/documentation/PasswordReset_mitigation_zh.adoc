== 如何防止密码重置功能被滥用

了解如何滥用密码重置功能后，你现在也应该知道如何保护自己的网站免受此类攻击。如果想要详细了解所有缓解方法，请参阅：https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html

本课程将总结上述备忘单中的要点。

=== 如何使用安全问题验证用户
安全问题是一种简单的方式，可以在不要求用户提供验证数据的情况下了解用户信息是否有效。问题在于，安全问题的类型并不多，而且许多用户的答案都相同。这使攻击者很容易猜测问题和答案。

让用户自行决定要回答的问题，可以增加猜中安全问题的难度。更多信息请参阅：https://cheatsheetseries.owasp.org/cheatsheets/Choosing_and_Using_Security_Questions_Cheat_Sheet.html#user-defined-security-questions

=== 通过网络发送数据
通过网络以任何方向发送的所有内容都可能被攻击者读取。有些数据会让攻击者更容易收集用户账户的关键信息，从而绕过登录和密码重置限制。因此，在密码重置过程中，尽量不要发送并非由用户主动输入的账户信息（如用户名、电子邮件地址等）。

例如：通过电子邮件向用户发送密码重置链接时，绝不要将用户名包含在密码重置表单中！用户无需在表单上看到自己的用户名，因为正常用户本来就知道自己的用户名。尽可能增加攻击者收集额外信息的难度。

=== 关于密码重置令牌
密码重置令牌让用户可以重置密码，而无需提供本质上安全的用户验证信息。因此，令牌本身必须安全且难以猜测。令牌有效期应较短，并且用户成功重置密码后令牌应失效。

=== 记录用户操作
仅靠日志记录无法阻止攻击，但有助于确定攻击是否发生，以及攻击者尝试如何绕过安全措施。你还可以通过日志判断账户是否真的遭到劫持，以及是否需要将账户交还给其合法用户。可以记录的操作包括：安全问题如何被回答？访问密码重置链接的时间与发送电子邮件的时间相比如何？是否出现过失败尝试？

=== 双因素身份验证
通过两种或更多独立方式、使用两台或更多独立设备进行身份验证，总是更加安全。用户重置密码时，可以要求他们输入通过短信、Messenger 或类似方式发送的验证码。这会增加攻击者绕过验证流程的难度，因为他们需要实际接触另一台设备。
另一方面，这要求用户提供额外的联系方式，并非所有人都愿意这样做。

=== 延伸阅读
我们强烈建议进一步阅读简介中链接的备忘单！密码重置功能如果实现不当，很容易被攻击者滥用。遵循这里及备忘单中的一些建议，就能增加攻击者滥用该功能的难度！
