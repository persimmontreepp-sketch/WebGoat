== 安全密钥、通行密钥与 WebAuthn

密码可能被猜中、重复使用、泄露或遭受钓鱼攻击。通过短信发送或由应用生成的一次性验证码能有所改善，但攻击者仍可运行仿冒网站，向受害者索要验证码并立即使用。

*FIDO2* 使用公钥密码学取代共享机密。它包含两项规范：

* *WebAuthn*（W3C）：网站用于与浏览器通信的 JavaScript API（`navigator.credentials.create()` / `navigator.credentials.get()`），以及服务器接收的数据格式。
* *CTAP2*（FIDO 联盟）：浏览器或操作系统与身份验证器通信时使用的协议，例如通过 USB、NFC 或蓝牙与安全密钥通信。

身份验证器会为每个网站创建新的密钥对。私钥永远不会离开身份验证器；网站只保存公钥。由于浏览器会告诉身份验证器哪个网站正在发起请求，并将来源加入签名数据，因此为 `goatbank.example` 创建的凭据不能用于 `goatbank-login.example`。这让 WebAuthn 能够抵御网络钓鱼。

=== 安全性取决于服务器

浏览器和身份验证器会完成各自的工作，但*依赖方（网站）必须验证收到的所有内容*。规范为注册和身份验证流程列出了二十多项验证步骤。自行实现或错误使用库的开发人员很容易漏掉其中某一步。一次验证缺失，就可能让“无法钓鱼”的身份验证变成账户接管。

=== 课程目标

完成本课程后，你将能够：

* 了解身份验证器、安全密钥、通行密钥，以及*注册*和*身份验证*流程中交换的数据；
* 利用注册漏洞，将自己的安全密钥绑定到其他人的账户；
* 利用身份验证漏洞，重放捕获的登录请求；
* 了解其他常见的实现错误以及如何防范；
* （额外内容）使用真实的漫游式安全密钥注册并登录，连接到执行全部验证的服务器。
