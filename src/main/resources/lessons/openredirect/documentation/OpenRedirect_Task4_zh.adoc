== 绕过双重编码检查

一些过滤器在验证前只对参数解码一次。如果稍后（由框架组件、代理、日志流水线等）再次解码用户输入，实际目标就可能改变。

目标：

* 提供一个 URL，在*解码一次后*看起来以可信主机 `https://webgoat.local` 开头，但在*解码两次后*，实际解析到的主机由攻击者控制。

技巧：

* 对 `@` 符号进行双重编码，使第一次解码后仍保留编码形式（`%40`），只有第二次解码才会显现用户信息分隔符。

示例：

* `https://webgoat.local%2540evil.com`
  * 第一次解码 -> `https://webgoat.local%40evil.com`（对朴素的前缀检查来说仍像是内部地址）
  * 第二次解码 -> `https://webgoat.local@evil.com`（实际主机为 `evil.com`）

成功后，调试输出将显示：

* `AppearsInternalAfter1: true`
* 第一次解析的主机是内部主机
* 第二次解析的主机是外部主机

试着用其他字符组合（例如 `%252F` => `%2F`）进行变化，观察多次解码如何改变 URL 的结构。
