== 挑战——存在缺陷的规范化

新的“修复”尝试在单次解码并转为小写后，将所有以 `http(s)://webgoat.local` 开头的内容视为可信。

但是，URL 可以在 `@` 符号前包含用户信息部分。代码只检查字符串前缀，没有验证实际主机名。

目标：

* 提供一个看起来以可信主机开头，但解析后实际主机为外部主机的值。

可以尝试以下载荷：

* `https://webgoat.local@evil.com`（用户信息技巧）
* `https://webgoat.local.evil.com`（子域名——是否通过前缀检查取决于代码）
* 编码后的用户信息：`https://webgoat.local%40evil.com`（如果有额外规范化处理）

如果调试输出显示 `AppearsInternal: true`，但 `RealHost` 是外部域名，则表示你成功了。
