== 防护与安全模式

开放重定向的关键防御措施：

. 优先在服务器端将短令牌或数字 ID 映射到已知的内部目标。
. 严格实施主机名精确允许列表（端口可选），比较前先进行规范解析。
. 如果业务逻辑不明确需要，应拒绝用户提供的绝对 URL。
. 如果必须支持外部合作伙伴，将合作伙伴目标存储在配置中，并通过 ID 引用。
. 避免使用朴素的子串或 `startsWith` 检查；先规范化（转小写、删除尾部句点），再比较完整主机名。
. 不要在未编码的情况下将不可信 URL 反映给用户（避免引发更复杂的 XSS 问题）。

安全示例使用 `/OpenRedirect/safe?destId=2` 表单，将整数 ID 映射到内部相对路径。

延伸阅读：

* OWASP 备忘单：未验证的重定向和转发
* 考虑改进用户体验，消除任意登录后重定向的需求（使用有状态的服务器端跳转流程）。
