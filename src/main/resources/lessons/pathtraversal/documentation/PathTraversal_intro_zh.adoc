=== 路径遍历

路径（目录）遍历是一种漏洞，攻击者可借此访问或存储应用程序所在位置之外的文件和目录。它可能导致读取其他目录中的文件；在文件上传场景下，还可能覆盖关键系统文件。

=== 它是如何工作的？

例如，假设某应用托管文件，访问格式如下：`http://example.com/file=report.pdf`。作为攻击者，你当然也想访问其他文件，于是尝试 `http://example.com/file=../../../../../etc/passwd.`。此时，你试图一路返回文件系统根目录，再进入 `/etc/passwd` 以获取该文件。`../` 称为 dot-dot-slash（点点斜杠），也是这种攻击的另一种叫法。

当然，这是一个直接的例子；框架通常实现了控制，因此大多数情况下不会奏效。我们需要更有创造性，在发送请求前对 `../` 进行编码。例如，对 `../` 进行 URL 编码后会得到 `%2e%2e%2f`，接收请求的 Web 服务器会再次将其解码为 `../`。

另外，如果应用没有过滤这些编码，双重编码也可能奏效。当系统 A 调用系统 B 时，可能需要双重编码。系统 A 只解码一次，再将仍处于编码状态的 URL 传给系统 B。
