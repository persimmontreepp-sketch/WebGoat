== 什么是 SQL 注入？

SQL 注入（也称 SQLi）是最常见的 Web 攻击技术之一。*SQL 注入攻击是指攻击者通过客户端发送给应用的 SQL 查询输入，插入或“注入”恶意代码。*如果处理不当，SQL 注入会严重影响数据完整性和安全性。

当客户端未经筛选的数据（例如搜索框中的输入）进入应用自身的 SQL 解释器时，就可能发生 SQL 注入。如果应用没有正确清理用户输入（例如使用预处理语句或类似机制），或没有过滤特殊字符，黑客就能利用底层 SQL 语句。+
例如，如果没有过滤 SQL 元字符 *--*（注释掉该行剩余内容）或 *;*（结束一条 SQL 查询），就可能发生 SQL 注入。

== SQL 注入示例

例如，假设一个 Web 应用允许用户只需在表单字段中输入用户名，就能获取用户信息。用户输入会发送到服务器，并被插入 SQL 查询中，然后由 SQL 解释器执行。

用于从数据库获取用户信息的 SQL 查询如下：+
-------------------------------------------------------
"SELECT * FROM users WHERE name = '" + userName + "'";
-------------------------------------------------------

变量 *userName* 保存来自客户端的输入，并将其“注入”查询中。+
如果输入 Smith，查询将变成：
-------------------------------------------------------
"SELECT * FROM users WHERE name = 'Smith'";
-------------------------------------------------------
并返回名为 Smith 的用户的所有数据。

{nbsp} +
如果攻击者输入包含对 SQL 解释器具有“特殊”含义的字符或字符串（例如 *;*、*--* 或 *'*）的数据，而这些数据没有经过正确清理或验证，攻击者就可以修改 SQL 查询的预期行为，以便在数据库上执行其他（恶意）操作。
