== 盲注

盲注是一种 SQL 注入攻击：攻击者向数据库提出“真”或“假”问题，并根据应用的响应来判断答案。当 Web 应用配置为显示通用错误消息、却没有修复易受 SQL 注入影响的代码时，攻击者通常会采用这种攻击。

=== 区别

先来看看普通 SQL 注入与盲注的区别。普通 SQL 注入中，数据库错误消息会显示出来，并提供足够信息来推断查询的工作方式。如果是基于 UNION 的 SQL 注入，应用则不会直接在网页中反映信息。因此，如果没有任何信息显示出来，你就需要根据真/假语句开始向数据库提问。这就是盲注更难利用的原因。

盲注有多种类型：基于内容的盲注和基于时间的盲注。

=== 示例

在这个例子中，我们根据唯一 ID 向数据库提出一个布尔问题。假设 URL 如下：`https://my-shop.com?article=4`
在服务器端，该查询会被转换为：

----
SELECT * FROM articles WHERE article_id = 4
----

如果要利用漏洞，可以将 URL 修改为：`https://shop.example.com?article=4 AND 1=1`
它将被转换为：

----
SELECT * FROM articles WHERE article_id = 4 and 1 = 1
----

如果浏览器返回与访问 `https://shop.example.com?article=4` 时相同的页面，就说明该网站可能存在盲注漏洞。
如果浏览器返回找不到页面或其他内容，则盲注可能无法奏效。
现在可以修改 SQL 查询并测试，例如：`https://shop.example.com?article=4 AND 1=2`。由于查询结果为假，因此不会返回任何内容。

我们实际上如何利用这种方式？上面只向数据库提出了一个简单的问题，但也可以使用如下 URL：`https://shop.example.com?article=4 AND substring(database_version(),1,1) = 2`

通常，你会先确定数据库的类型。了解数据库类型后，就可以查找该数据库的系统表，枚举数据库中的所有表。利用这些信息，你便可以从所有表中获取数据并转储数据库。请注意，如果数据库权限配置正确，这种方法可能无效（即 Web 应用用于连接数据库的用户无法查询系统表）。

另一种方式称为基于时间的 SQL 注入。这种情况下，你会要求数据库在返回结果前等待一段时间。如果完全看不到任何差别，可以使用此方法。可以尝试如下方式：

----
article = 4; sleep(10) --
----
