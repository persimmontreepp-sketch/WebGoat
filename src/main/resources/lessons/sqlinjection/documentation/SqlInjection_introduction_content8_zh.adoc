== 通过字符串 SQL 注入破坏机密性
如果系统容易受到 SQL 注入攻击，其 CIA 三要素中的某些方面就很容易遭到破坏（如果你不熟悉 CIA 三要素，请参阅通用类别下的 CIA 三要素课程）。
接下来的三门课程将介绍如何使用*字符串 SQL 注入*或*查询链接*等技术破坏 CIA 三要素中的各个方面。

本课程将探讨*机密性*。
攻击者可以轻易地通过 SQL 注入破坏机密性；例如，成功的 SQL 注入可以让攻击者读取数据库中的信用卡号等敏感数据。

=== 什么是字符串 SQL 注入？
如果应用仅仅通过将用户提供的字符串拼接到查询中来构造 SQL 查询，那么它很可能容易受到字符串 SQL 注入攻击。+
更具体地说，如果用户提供的字符串未经清理或预处理就被直接拼接到 SQL 查询中，那么只需在输入字段中插入引号，就可能修改查询行为。
例如，你可以用引号结束字符串参数，然后在后面输入自己的 SQL 语句。

=== 轮到你了！
你是 John *Smith*，在一家大型公司工作。公司有一个内部系统，允许所有员工查看自己的内部数据，例如所在部门和薪水。

员工必须使用唯一的*身份验证 TAN* 才能查看自己的数据。+
你当前的 TAN 是 *3SL99A*。

由于你总想成为薪酬最高的员工，因此你想利用该系统，不再只查看自己的内部数据，而是_查看所有同事的数据_，了解他们当前的薪水。

使用下方表单，试着从 *employees* 表中获取所有员工数据。你不需要知道任何特定员工姓名或 TAN 即可获得所需信息。+
你已经发现执行请求的查询如下：
------------------------------------------------------------
"SELECT * FROM employees WHERE last_name = '" + name + "' AND auth_tan = '" + auth_tan + "'";
