=== XXE 示例

来看一个 XXE 注入示例。上一节介绍了 XML 实体可以这样使用：

[source, xml]
----
<?xml version="1.0" standalone="yes" ?>
<!DOCTYPE author [
  <!ELEMENT author (#PCDATA)>
  <!ENTITY js "Jo Smith">
]>
<author>&js;</author>
----

=== 外部 DTD 声明

定义这些实体后，也可以在外部文件中定义另一个 DTD，例如：

[source, xml]
----
<?xml version="1.0"?>
<!DOCTYPE note SYSTEM "email.dtd">
<email>
  <to>webgoat@webgoat.org</to>
  <from>webwolf@webwolf.org</from>
  <subject>Your app is great, but contains flaws</subject>
  <body>Hi, your application contains some SQL injections</body>
</email>
----

`email.dtd` 的定义如下：

[source, dtd]
----
<!ELEMENT email (to,from,title,body)>
<!ELEMENT to (#PCDATA)>
<!ELEMENT from (#PCDATA)>
<!ELEMENT subject (#PCDATA)>
<!ELEMENT body (#PCDATA)>
----

=== XXE

如果 XML 解析器配置为允许外部 DTD 或实体，我们就可以将下面的 XML 片段修改为：

[source, xml]
----
<?xml version="1.0" encoding="utf-8"?>
<!DOCTYPE author [
  <!ENTITY js SYSTEM "file:///etc/passwd">
]>
<author>&js;</author>
----

现在会发生什么？我们定义了一个从本地文件系统中读取内容的引用，XML 解析器会加载该文件，并将文件内容插入实体出现的位置。假设 XML 消息会返回给用户，消息就会如下所示：

[role="lesson-image"]
image::images/etc_password.png[Password]

注意：你可以始终将额外的文档类型定义（DOCTYPE）添加到 XML 文档中。如果解析器设置允许处理外部实体，那么这就是开始发现 XXE 注入漏洞的有利条件。
