=== 什么是 XML 实体？

XML 实体允许定义标签，并在解析 XML 文档时用内容替换这些标签。一般有三种实体：

* 内部实体
* 外部实体
* 参数实体

实体必须在文档类型定义（DTD）中创建。来看一个示例：

如你所见，解析器处理 XML 文档后，会将已定义的实体 `js` 替换为已定义的常量“Jo Smith”。这有许多优点，例如可以只在一个位置将 `js` 更改为“John Smith”。

在 Java 应用中，可以使用 XML 将客户端数据发送到服务器。我们都熟悉 JSON API，也可以使用 XML 传递信息。大多数情况下，框架会根据 XML 结构自动填充 Java 对象，例如：

=== 什么是 XXE 注入？

XML 外部实体攻击是一种针对解析 XML 输入的应用的攻击。当包含外部实体引用的 XML 输入被配置不安全的 XML 解析器处理时，就会发生此攻击。它可能导致机密数据泄露、拒绝服务、服务端请求伪造、从解析器所在机器的视角进行端口扫描，以及其他系统影响。

攻击可能会泄露本地文件，这些文件可能包含密码或用户私人数据等敏感信息。攻击者可以在系统标识符中使用 `file:` 方案或相对路径。由于攻击发生在处理 XML 文档的应用上下文中，攻击者可能利用此受信任的应用转向其他内部系统，通过 HTTP(S) 请求泄露其他内部内容，或针对未受保护的内部服务发动 CSRF 攻击。在某些情况下，易受客户端内存破坏问题影响的 XML 处理器库可能因访问恶意 URI 而被利用，从而以应用账户权限执行任意代码。其他攻击还可以访问持续返回数据的本地资源，如果没有释放过多线程或进程，就可能影响应用可用性。

通常可以区分以下几类 XXE 攻击：

* 经典型：在本地 DTD 中包含外部实体
* 盲注型：响应中不显示输出和/或错误
* 错误型：尝试在错误消息中获取资源内容
